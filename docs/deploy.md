# Викладання теми на бойовий сайт

Як встановити й увімкнути `belosvyat-redesign` на https://belosvyat.com.ua/
замість старої теми (Artisteer, 2011) так, щоб нічого не загубити, і як
повернутися назад, якщо щось піде не так.

Коротко: **резервна копія → архів із git → завантажити через адмінку →
переглянути без активації → активувати → перенести налаштування → статична
головна й меню (`front-page-setup.md`) → перевірка.**

## 0. Перед початком

- **Бойовий сервер:** WordPress 6.0+, PHP 7.4+ (див. «Майстерня → Здоров'я
  сайту → Інформація → Сервер»). На старішому PHP тема впаде з фатальною
  помилкою.
- **Час:** оберіть годину з найменшим трафіком. Між активацією теми й
  кроком 6 головна сторінка виглядатиме як стрічка новин — це нормально, але
  краще, щоб цього ніхто не бачив.
- **Доступ:** обліковий запис адміністратора. Для скриптів із кроку 6 —
  ще SSH; без нього все робиться вручну в адмінці.

## 1. Резервна копія

Обов'язково — і бази, і файлів. Тема сама нічого не видаляє, але кроки 5–6
змінюють налаштування, меню та створюють сторінки.

- через панель хостингу (якщо є бекапи — зробіть знімок вручну саме зараз);
- або плагіном (UpdraftPlus, All-in-One WP Migration тощо);
- або з SSH: `wp db export backup-$(date +%F).sql`.

Окремо **запишіть назву (теку) поточної теми** — «Вигляд → Теми», активна тема.
Вона знадобиться для відкату.

## 2. Зібрати архів теми

Архів робимо з git, а не стискаємо теку вручну: так у нього не потрапить `.git`
(~3 МБ історії) та випадкові локальні файли.

Із кореня теми (PowerShell або Git Bash):

```
git status          # має бути "working tree clean"
git archive --format=zip --prefix=belosvyat-redesign/ -o ../belosvyat-redesign.zip HEAD
```

Важливо:

- **`git archive` бере лише закомічене.** Незакомічені зміни в архів не
  потраплять — спершу закомітьте.
- **Тека всередині архіву має називатися саме `belosvyat-redesign`** (це робить
  `--prefix`). Від назви теки залежить ключ налаштувань теми в базі
  (`theme_mods_belosvyat-redesign`) — інша назва = порожній Кастомайзер.
  Не перейменовуйте zip-файл на щось на кшталт `belosvyat-redesign-v2.zip`
  і не пакуйте вміст без теки.
- Розмір архіву ~0,5 МБ — у ліміт завантаження адмінки вміщається.

Архів з'явиться поруч із темою: `wp-content/themes/belosvyat-redesign.zip`.
Після завантаження на бій його можна видалити.

## 3. Завантажити тему (без активації)

**Вигляд → Теми → Додати нову тему → Завантажити тему** → вибрати
`belosvyat-redesign.zip` → «Встановити».

Після встановлення **не натискайте «Активувати»**. Тема просто лежить поруч
зі старою.

*Без доступу до адмінки (або якщо хостинг обмежує завантаження):* розпакуйте
архів і залийте теку `belosvyat-redesign` через FTP/SFTP у
`wp-content/themes/`.

## 4. Переглянути, не вмикаючи

**Вигляд → Теми** → на картці нової теми **«Попередній перегляд»**. Відкриється
Кастомайзер із новою темою — відвідувачі в цей час бачать стару.

Перевірте:

- шапку, меню (розташування «Головне меню» має бути заповнене), підвал;
- запис, сторінку, архів рубрики, пошук, сторінки з шаблоном «One Column»;
- віджети в бічній панелі.

Тут же можна одразу виставити логотип, зображення шапки та тексти (див.
крок 5) і натиснути **«Активувати та опублікувати»** — тоді тема ввімкнеться
вже з налаштуваннями. Якщо щось не так — просто закрийте Кастомайзер, нічого
не зміниться.

## 5. Активувати й перенести налаштування

Якщо не активували на кроці 4: **Вигляд → Теми → Активувати**.

### Що переноситься саме

| Що | Чому |
|---|---|
| Записи, сторінки, медіа, рубрики, плагіни | не залежать від теми |
| Віджети | ідентифікатори областей збережені зі старої теми |
| Прив'язка меню до «Головне меню» | розташування `primary-menu` має ту саму назву, WordPress зіставляє його сам |
| Сторінки з шаблоном «One Column» | файл `onecolumn-page.php` збережено |

### Що треба виставити вручну

Налаштування Кастомайзера WordPress зберігає **окремо для кожної теми**, тож
зі старої вони не переїдуть. А **локальні налаштування з Local теж не
переїдуть** — вони в локальній базі, не в архіві. Заповніть на бою:

- **Вигляд → Налаштувати → Логотип** — логотип у шапці;
- **Вигляд → Налаштувати → Зображення шапки** — фон банера (без нього —
  градієнт у кольорах теми). Рекомендований розмір 1920×720;
- **Вигляд → Налаштувати → Банер на головній** — заголовок, підзаголовок,
  кнопка;
- **Вигляд → Налаштувати → Підвал** — текст підвалу (можна з `[year]`);
- **Вигляд → Меню → Керування розташуваннями** — переконайтеся, що «Головне
  меню» = «навігація по сайту». «Додаткове меню» й «Меню у підвалі» нові —
  заповніть, якщо потрібні;
- **Вигляд → Віджети** — пробіжіться очима; якщо WordPress переніс щось у
  «Неактивні віджети», поверніть на місце.

## 6. Статична головна, `/news/` і меню

Це окрема процедура з власною інструкцією —
**[`docs/front-page-setup.md`](front-page-setup.md)**. Коротко, з SSH:

```
cd /шлях/до/wp-content/themes/belosvyat-redesign
php tools/front-page-migration.php
php tools/menu-restructure.php
```

Саме в такому порядку: другий скрипт потребує результату першого. Обидва
ідемпотентні, з браузера не запускаються (403). Без SSH — ручний варіант
у тій самій інструкції.

Наприкінці — **Налаштування → Постійні посилання → «Зберегти зміни»**.

## 7. Після переходу

- **Скинути кеш**: плагін кешування, кеш хостингу, Cloudflare (якщо є).
  Інакше відвідувачі ще якийсь час бачитимуть стару верстку. CSS/JS теми
  кешувати не заважає — у посиланнях на них версія з часом зміни файлу.
- **Мініатюри (за бажанням).** Тема додає розміри `belosvyat-card` (720×460) і
  `belosvyat-hero` (1600×720). Для старих зображень їх немає — WordPress
  підставить найближчий наявний розмір, тож нічого не зламається, але картки
  вантажитимуть більші файли. Виправляється плагіном Regenerate Thumbnails
  або `wp media regenerate --only-missing` (довго на великій медіатеці — краще
  вночі).

## 8. Перевірка

- [ ] `/` — головна з банером і п'ятьма розділами;
- [ ] `/news/` — стрічка новин, бічна панель, пагінація;
- [ ] довільний старий запис (2012–2015) — картинка в картці є, текст і
      таблиці не розлазяться;
- [ ] сторінка з шаблоном «One Column»;
- [ ] пошук знаходить і показує результати;
- [ ] мобільна ширина: бургер, підменю, пошук відкриваються;
- [ ] GTranslate перемикає мову;
- [ ] у `<title>` вкладки — назва сайту;
- [ ] «Здоров'я сайту» не показує нових критичних проблем; у журналі помилок
      PHP немає нових записів від `themes/belosvyat-redesign`.

Повний список перевірок для головної — у `front-page-setup.md`.

## Відкат

1. **Вигляд → Теми** → активувати стару тему (назва з кроку 1). Її віджети,
   меню й налаштування Кастомайзера нікуди не ділися — вони збережені окремо.
2. Якщо робили крок 6 — **Налаштування → Читання** → «Ваші останні записи»
   (див. «Відкат» у `front-page-setup.md`). Меню старій темі доведеться
   підправити вручну: пункти, прибрані скриптом, треба додати знову.
3. Скинути кеш.

Якщо адмінка недоступна (білий екран після активації) — перейменуйте через
FTP/SFTP теку `wp-content/themes/belosvyat-redesign` на будь-яку іншу:
WordPress сам повернеться на тему за замовчуванням, і в адмінку можна буде
зайти, щоб увімкнути стару. Крайній варіант — відновити бекап із кроку 1.

## Наступні оновлення теми

1. Закомітити зміни, зібрати архів тією ж командою з кроку 2.
2. **Вигляд → Теми → Додати нову тему → Завантажити тему** → той самий zip.
3. WordPress помітить, що тема вже є, і запропонує **«Замінити поточну
   завантаженою»** — погодитись. Налаштування Кастомайзера, меню й віджети
   лишаються.
4. Скинути кеш.

Змінюючи тему, підвищуйте `Version` у `style.css` і `BELOSVYAT_VERSION` у
`functions.php` — на екрані заміни буде видно, яка версія стоїть і яка
приходить.
